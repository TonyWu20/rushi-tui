# TUI feature requests, 2026-10-19: detail

Full detail for the "New requests (2026-10-19)" entries of
`docs/tui_feature_requests_from_human.md`. The index keeps one
line per request. This doc keeps the request text, the design
decisions, and the shipped notes.

## oneshot-branch-summarize

- [x] `Summarize the branch` needs no pre-existing `rewind` marker.

Request text (verbatim): "The current design of `Summarize the
branch` invoke in `rushi-tui` needs a marker of `abandoned` on the
branch first. This does not make sense. The original intention is
when a user pick this option on the selected entry, it does the two
things in one-shot. First, the context is rewounded to the selected
entry, then the abandoned branch is summarized. Finally, the summary
is appended to the context up to the rewounded entry." The reporter
also reported that the two-step workaround
(`Rewind without summary` then `Summarize the branch` on the same
entry) does not work either.

### Root cause

The 2026-09-16 design (docs/tree-ui-design-from-human.md) split the
work: `Rewind without summary` appends the `rewind` marker, and the
summarize options spawn `bin/compact --branch` on the open span of
the last marker. The two-step flow dead-ends:

- A `user_message` pick rewinds in `before` mode. The picked event
  leaves the active path, and the active-path commit guard refuses
  the summarize on the same entry.
- A tail pick abandons an empty open span. The kernel no-ops, and
  no summary marker lands.

### Decisions

- The picked event becomes the rewind target. Committing either
  summarize option appends the `rewind` marker (mode `on`, reason
  `tui_pick`), then spawns `bin/compact --branch`. One user action,
  one fork, one summary.
- Mode `on` for every event kind: the picked event stays in the
  context. No text is restored to the input box (that stays a
  `Rewind without summary` behavior).
- The model context at the marker reads: the system prompt, the
  context up to the picked event, the branch summary, then the new
  user context that follows.
- An off-active-path pick is allowed: the kernel re-enters the
  abandoned branch at the target. The `seq_in_ranges` commit guard
  is removed with the marker prerequisite.
- No kernel change. `bin/compact --branch` already summarizes the
  open span of the most recent `rewind` marker. The flow is a TUI
  composition, and the marker append runs before the spawn so the
  compact child sees it.

### Shipped 2026-10-19

- `bin/tui/src/app.rs`: `Action::BranchSummarize` carries
  `target_seq`; `commit_tree_option` drops the
  `rewind_active_ranges` guard; the custom-prompt capture remembers
  the picked seq (`branch_prompt_target`).
- `bin/tui/src/main.rs`: the `BranchSummarize` handler appends the
  `rewind` marker through the port, then spawns the compact.
- Tests: the commit tests assert the target seq; the pty smoke test
  seeds a linear log (no marker), picks the non-tail event, and
  asserts the one-shot marker lands in `events.jsonl` before the
  spawn.
