## message-panel-timestamps

- [x] Add the event timestamp to the user-message panel
      title and the assistant reply panel title.

Request text (verbatim): "Add the timestamp to the user message
and assistant message reply box title."

Design decisions (2026-10-07):

1. Timestamp source: the event log `ts` field (RFC 3339, UTC).
   Read through `Event::get_str("ts")` in `bin/tui/src/render.rs`.
2. Display: local time, `HH:MM:SS`. The log stores UTC; the
   reader watches the transcript in local time.
3. The user panel title grows from `User` to
   `User · HH:MM:SS` (the `·` separator, one space on each
   side).
4. The assistant reply (report) panel gains a title: the
   bare event timestamp `HH:MM:SS`, no role word (the user
   dropped the `Assistant` label). The panel carries no title
   today (docs/tui-turn-fold.md "Final message panel").
5. A missing or unparseable `ts` keeps the current titles:
   the user panel keeps `User`; the report panel keeps no
   title. Old logs and the snapshot fixtures (`"ts":"t"`)
   render unchanged.

Shipped 2026-10-07 (branch `feat/message-panel-timestamps`):
`event_ts_local` in `bin/tui/src/render.rs` reads the event
`ts` (RFC 3339, UTC) and renders it in local time as
`HH:MM:SS`. `user_box_rows` and `report_box_rows` take the
formatted `ts` and build the titled top border through the
shared `message_box_rows`. The `event_lines` `UserMessage`
arm and the `AssistantMessage` `final_report` arm pass the
event timestamp. `docs/tui-turn-fold.md` "Final message
panel" now names the titled boxes.
Tests: `user_box_title_carries_the_event_timestamp`,
`report_box_title_carries_the_event_timestamp`, and
`event_ts_local_shapes_the_log_ts` in `render.rs`
(`user_box_tests`).

Scope: the transcript panel builders in `bin/tui/src/render.rs`
(`user_box_rows`, `report_box_rows`, the `event_lines`
`UserMessage` and `AssistantMessage` arms). Browse mode and the
tree preview reuse the same transcript lines and pick up the
title with no change of their own. The pending-message blocks
(the `steer`/`follow` queues, docs/tui-pending-user-messages.md)
show messages that have no log `ts` yet and stay plain.
