# TUI feature requests, 2026-10-08: detail

Full detail for the "New requests (2026-10-08)" entries of

## focus-switch-regression

- [x] The `Ctrl+Shift+P` focus switch in the tree-view palette
      appears ineffective. Change the description.

Request text (verbatim): "The `ctrl+shift+p` switch focus function
in the `tree` view palette seems to ineffective now. Investigate
it. When root cause is found, report to me first." Follow-up
(verbatim): "It works with `Shift + Tab`. I suggest to change the
description."

Investigation (2026-10-08, session `focus-switch-regression`):

1. The focus cycler is correct in code. `PaletteState::
   toggle_focus` walks `Input -> List -> Preview -> Input` in the
   tree stage. The full `App::press` dispatcher and the live PTY
   confirm the cycle on the kitty-protocol bytes
   (`\x1b[80;6u`, codepoint 80 = `P`, modifier 6 = 1+shift+ctrl).
2. The toggle only reaches the app when the terminal reports the
   Shift modifier through the kitty keyboard protocol. On the
   reporter's terminal `Ctrl+Shift+P` arrives as the legacy byte
   0x10. `key_input` maps it to `Key::CtrlP`, the preview-pane
   toggle. The focus never moves. That is the "ineffective"
   symptom.
3. `BackTab` (`Shift+Tab`) is terminal-independent: a legacy
   terminal sends `ESC[Z`, and a kitty-protocol terminal sends
   `\x1b[9;2u`. crossterm 0.29 maps both to `KeyCode::BackTab`.
   The reporter confirms `Shift+Tab` toggles the focus in their
   terminal.
4. crossterm parses `\x1b[>1u` (the `PushKeyboardEnhancementFlags`
   request) correctly. Terminals that do not speak the protocol
   keep sending legacy bytes, so `Ctrl+Shift+P` stays indistinct
   from `Ctrl+P` there.

Decision (2026-10-08): the user's instruction — change the
description. `BackTab` (`Shift+Tab`) is now the advertised focus
key. The input-bar hints read `shift-tab focus`. `Ctrl+Shift+P`
stays bound for kitty-protocol terminals, but it is no longer the
advertised key. The no-op guard (the toggle is a no-op while the
preview pane is hidden, phase-2 item 4) is unchanged.

Shipped 2026-10-08 (session `focus-switch-regression`): the three
input-bar hint strings read `shift-tab focus` instead of
`ctrl-shift-p focus` (`bin/tui/src/palette/render.rs` the flat
palette stage, `bin/tui/src/render.rs` the picker,
`bin/tui/src/app.rs` the tree stage). The key-contract tables of
`docs/tree-ui-design-from-human-phase-2.md` and
`docs/tui-command-palette.md` name `BackTab` (`Shift+Tab`) first
and mark `Ctrl+Shift+P` as kitty-protocol-only. The key lists of
`docs/tui-file-picker.md` match. The phase-2 status line records
the refinement.

Tests: the snapshot set is unchanged (the hint change lands past
the snapshot terminal width). The unit suite is green. The PTY
case `csi_u_ctrl_shift_p_toggles_preview_focus` still passes:
the kitty-protocol binding is unchanged.
